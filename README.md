# ربات مدیریتی تلگرام (آپلود و اجرای خودکار بات‌ها)

## چیکار می‌کنه؟
1. یک فایل بات تک‌فایلی (`.py`, `.js`, یا `.php`) براش بفرست.
2. اگه بات به پکیج/کتابخونه خاصی نیاز داره، فایل وابستگیِ مربوطه رو بفرست
   (`requirements.txt` برای پایتون، `package.json` برای Node، `composer.json` برای PHP) — اختیاریه.
3. توکن API اون بات رو به‌صورت یه پیام متنی جدا بفرست.

ربات به‌صورت خودکار:
- برای پایتون: یه **virtualenv مجزا** برای همون بات می‌سازه، چند کتابخونه‌ی پایه‌ی بات‌سازی
  (`python-telegram-bot`, `pyTelegramBotAPI`, `aiogram`, `requests`) رو نصب می‌کنه، و اگه
  `requirements.txt` فرستاده باشی، اونم نصب می‌کنه.
- برای Node: `npm install` می‌زنه (اگه `package.json` نباشه، چند کتابخونه‌ی پایه مثل
  `node-telegram-bot-api`, `telegraf`, `axios` رو نصب می‌کنه).
- برای PHP: اگه `composer.json` فرستاده باشی، `composer install` می‌زنه.

سپس فایل رو با interpreter مناسب اجرا می‌کنه و توکن رو به‌عنوان متغیر محیطی `TOKEN` (و `BOT_TOKEN`)
در اختیارش می‌ذاره.

بات‌های آپلودی باید توکن رو از `os.environ["TOKEN"]` (پایتون)، `process.env.TOKEN` (Node) یا
`getenv('TOKEN')` (PHP) بخونن — نه اینکه هاردکد شده باشه.

⏳ نصب کتابخونه‌های پایه برای هر بات پایتونی چند ده ثانیه تا چند دقیقه طول می‌کشه (بسته به سرعت
اینترنت Railway) — طبیعیه، صبر کن پیام «🚀 اجرا شد» بیاد.

## دیپلوی روی Railway از طریق GitHub

1. محتویات این زیپ رو تو یه ریپوی GitHub پوش کن (فایل‌های پروژه‌ی قبلی نباید تو همون ریپو باشن).
2. تو Railway: New Project → **Deploy from GitHub repo** → ریپوت رو انتخاب کن.
3. مطمئن شو Builder روی **Dockerfile** تنظیم شده (نه Railpack) — Settings → بخش بالای صفحه.
4. تو تب **Variables** این دو تا رو ست کن:
   - `MANAGER_BOT_TOKEN` = توکن ربات مدیریتی (از BotFather)
   - `ADMIN_IDS` = آیدی عددی تلگرام خودت (با `/myid` از خودِ ربات می‌گیری)، اگه چند ادمین داری با کاما جدا کن: `111111,222222`
5. تو تب **Volumes** یه Volume به مسیر `/data/bots` وصل کن تا فایل‌های کاربرا با هر دیپلوی پاک نشن.
6. Deploy. با هر `git push` بعدی خودکار ری‌دیپلوی می‌شه.

## نقش‌ها (ادمین / کاربر عادی)

- **کاربر عادی**: فقط می‌تونه بات خودش رو بفرسته و اجرا کنه، و با `/list`, `/logs`, `/stop` فقط
  روی بات‌های خودش کار کنه. کاربر مسدود (`/ban`) اصلاً نمی‌تونه فایل جدید بفرسته.
- **ادمین** (آیدی‌ش تو `ADMIN_IDS` باشه): علاوه بر دستورات بالا، به این‌ها هم دسترسی داره:
  - `/listall` — لیست بات‌های همه‌ی کاربرا
  - `/stopuser <user_id> <نام_فایل>` — توقف بات هر کاربری
  - `/logsuser <user_id> <نام_فایل>` — لاگ بات هر کاربری
  - `/ban <user_id>` — مسدود کردن یه کاربر (بات‌های در حال اجراش هم متوقف می‌شن)
  - `/unban <user_id>` — رفع مسدودیت
  - `/banned` — لیست کاربرای مسدود

هر کاربری (ادمین یا نه) می‌تونه با `/myid` آیدی عددی تلگرام خودش رو ببینه.

**نکته:** دستورات ادمین (`/listall`, `/ban` و...) حتی تو منوی «/» تلگرام برای کاربرای عادی
نمایش داده نمی‌شن (فقط ادمین تو اتوکامپلیت می‌بینتشون)، ولی برای اطمینان بیشتر، اگه یه کاربر
عادی دستی هم تایپشون کنه، سرور دوباره چک می‌کنه و اجازه‌ی اجرا نمی‌ده.

## ماندگاری داده‌ها بعد از ری‌دیپلوی (Persistence)

با هر آپدیت از گیت‌هاب، Railway کانتینر رو از صفر می‌سازه و همه‌ی پروسه‌ها (از جمله بات‌های
در حال اجرا) کشته می‌شن. برای اینکه بعد از هر ری‌دیپلوی مجبور نباشی همه‌چی رو از اول بفرستی:

1. **حتماً یه Volume به مسیر `/data/bots` وصل کن** (Settings → Volumes). بدون این، با هر
   دیپلوی همه‌ی فایل‌ها، توکن‌ها، لیست کاربرای مسدود و venv/node_modules ها پاک می‌شن.
2. با Volume وصل، ربات موقع هر بار بالا اومدن (`post_init`) خودکار:
   - لیست کاربرای مسدود (`banned.json`) رو می‌خونه.
   - تمام بات‌هایی که آخرین وضعیتشون «فعال» بوده (یعنی کسی دستی `/stop`شون نکرده و کاربرشون
     هم بن نشده) رو دوباره اجرا می‌کنه، و به صاحب هر بات پیام «🔁 دوباره اجرا شد» می‌فرسته.
   - بات‌هایی که قبلاً با `/stop` یا `/ban` متوقف شدن، خودکار دوباره اجرا نمی‌شن (وضعیتشون
     «غیرفعال» ذخیره شده).
3. توکن هر بات به‌صورت متن ساده تو فایل `state.json` همون پوشه‌ی بات ذخیره می‌شه (نه رمزنگاری‌شده).
   چون این پنل برای استفاده‌ی شخصی/تیمی طراحی شده، اگه امنیت بالاتری لازم داری (مثلاً رمزنگاری
   توکن‌ها رو دیسک)، باید جداگانه اضافه بشه.

با این تنظیمات، بعد از هر `git push` جدید، فقط باید صبر کنی چند ثانیه تا بازیابی خودکار انجام
بشه؛ نیازی به فرستادن دوباره‌ی فایل‌ها و توکن‌ها نیست.


## محدودیت‌های مهم (حتماً بخون)
- **امنیت**: این نسخه فایل‌های آپلودی رو مستقیم روی همون سرور اجرا می‌کنه، بدون sandbox واقعی.
  اگه فایل مخرب باشه (مثلاً بی‌نهایت لوپ بزنه یا منابع رو بخوره)، کل سرور تحت تأثیر قرار می‌گیره.
  برای استفاده‌ی شخصی/فایل‌های مورد اعتماد خودت مناسبه؛ برای سرویس عمومی به کاربرای ناشناس، نیاز به
  ایزوله‌سازی جدی‌تر داری (مثلاً هر بات تو یه کانتینر جدا با محدودیت CPU/RAM/زمان).
- **حافظه**: لیست بات‌های در حال اجرا در RAM نگه‌داری می‌شه؛ با ری‌استارت شدن سرویس، این لیست
  پاک می‌شه (فایل‌ها اگه Volume وصل باشه می‌مونن، ولی باید دوباره توکن رو بفرستی تا اجرا بشن).
- **حجم فایل**: پیش‌فرض محدود به ۲۰ مگابایت (قابل تغییر در `MAX_FILE_SIZE_MB`).

## پر کردن خودکار متغیرهای config خام تو فایل

خیلی از فایل‌های تک‌فایلی به‌جای خوندن از env، مقادیر رو مستقیم بالای کد می‌نویسن، مثلاً:
```python
API_ID = 
API_HASH = "..."
BOT_TOKEN = "..."
OWNER_IDS = [...]
```
وقتی همچین فایلی رو بفرستی، ربات مدیریتی خودکار:
1. این ۴ متغیر (`API_ID`, `API_HASH`, `BOT_TOKEN`, `OWNER_IDS`) رو تو کد پیدا می‌کنه — حتی اگه
   از قبل یه چیزی (درست یا غلط) جلوشون نوشته شده باشه، پاکش می‌کنه.
2. یکی‌یکی مقدار هرکدوم رو ازت می‌پرسه (`API_ID` باید عدد باشه، `OWNER_IDS` می‌تونه چند آیدی
   با کاما جدا باشه).
3. بعد از تایپ هر مقدار، مستقیم همون لحظه تو فایل می‌نویسه و ذخیره می‌کنه.
4. وقتی همه پر شد، اگه بات به کتابخونه خاصی نیاز داره فایل وابستگی رو بفرست، وگرنه دستور
   **`/run`** رو بزن تا اجراش کنم.

اگه فایل هیچ‌کدوم از این متغیرها رو نداشته باشه (یعنی از env می‌خونه)، فلوی قبلی (فرستادن توکن
به‌صورت پیام متنی) دست‌نخورده باقی می‌مونه.
